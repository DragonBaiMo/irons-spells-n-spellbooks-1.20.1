# 铁魔法参数施法指令 Web 工具 PRD & PDR 文档

## 一、产品需求文档（PRD）

### 1. 项目背景与目标

- Iron's Spells 'n Spellbooks 当前已经通过参数化施法系统与 `skill-docs` 目录，实现了技能参数的文档化与可覆盖。
- 管理员可通过 `/iss cast` 指令 + JSON 参数，实现旁路施法与精细控制，但手写 JSON 麻烦且容易出错。
- 目标是做一个基于 TypeScript + HTML 的 Web 小工具，帮助管理员从技能文档中选择技能、配置参数，并一键生成：
  - 单行 JSON 参数串；
  - 完整的 `/iss cast` 指令。

### 2. 用户与使用场景

#### 2.1 主要用户

- 服务器管理员、地图作者、脚本作者：
  - 需要频繁测试技能、调整数值；
  - 需要为任务、命令方块、函数文件等生成标准化指令。

#### 2.2 典型场景

1. 管理员想测试某个技能的极限伤害：
   - 从列表中选择 `fireball`；
   - 将 `damageBase`、`damageScale` 调大；
   - 勾选 `consumeMana`、`triggerCooldown`，模拟真实施法；
   - 一键复制 `/iss cast` 指令，粘贴进游戏执行。

2. 地图作者需要为任务链预配置一组技能施放：
   - 为同一个技能制作多套参数预设（低难度 / 高难度）；
   - 生成多条 JSON 和指令，写入函数文件或命令方块。

3. 调试某个复杂技能（例如传送门、召唤类技能）：
   - 在 Web 端查看该技能的所有参数与默认值；
   - 快速调整 `maxRange`、`portalDurationTicks`、`summonDurationTicks` 等参数；
   - 多次生成指令，在游戏里反复测试效果。

### 3. 功能范围

#### 3.1 技能数据加载

- 从现有 `skill-docs/*.md` 中加载技能定义与参数信息。
- 能够解析以下信息：
  - 技能显示名：例如 `FireballSpell`；
  - 完整技能 ID：例如 `irons_spellbooks:fireball`；
  - 指令用技能 ID：`fireball`（从命名空间中剥离）；
  - 参数表：
    - 参数主键与别名（例如 `manaCost / baseManaCost`）；
    - 参数类型（INT / DOUBLE / FLOAT 等）；
    - 默认值；
    - 中文说明。
- 能够读取每个文档末尾的“说明”段落，并在界面中展示：
  - 至少包含“参数可在管理员通道中通过 SpellParameters 进行覆盖”；
  - 支持将将来新增的技能使用说明一并展示。

#### 3.2 技能列表与搜索

- 左侧展示所有技能列表，可滚动。
- 支持按以下条件筛选：
  - 全部技能；
  - 收藏技能（用户手动标记常用技能）。
- 支持搜索：
  - 可根据技能显示名、指令 ID（如 `fireball`）、完整 ID 片段模糊匹配。

#### 3.3 技能详情展示

- 右侧展示当前选中技能的基础信息：
  - 技能显示名（类名风格）；
  - 完整技能 ID；
  - 指令技能 ID（用于 `/iss cast`）。
- 展示技能说明：
  - 显示 `skill-docs` 中的“说明”段落；
  - 保留中文描述，帮助理解技能整体行为；
  - 若未来扩展额外说明（如“特殊行为”、“使用建议”），也在此处统一展示。

#### 3.4 施法基础参数配置

- 提供基础施法参数配置组件：
  - 施法者选择器：
    - 文本输入框，默认值为 `@s`；
    - 支持填写任意合法实体选择器或玩家名。
  - 技能等级：
    - 数字输入框，默认值可设为 5（可在实现阶段调整为配置项）；
    - 限制为正整数。
  - 目标实体：
    - 文本输入框，可为空；
    - 支持填入实体选择器、UUID 或保留为空（使用技能内部默认逻辑）。
- 通用控制参数（对应现有文档中的控制字段）：
  - `consumeMana`：是否消耗蓝量；
  - `triggerCooldown`：是否触发冷却；
  - `playEffects`：是否播放特效；
  - `bypassConditions`：是否绕过前置条件；
  - `showCastBar`：是否显示施法条。
- 用户通过勾选框控制上述布尔字段，默认值与现有文档保持一致：
  - 默认不消耗蓝、不触发冷却；
  - 默认播放特效；
  - 默认绕过前置条件；
  - 默认不显示施法条。

#### 3.5 技能参数配置（来自 skill-docs）

- 展示当前技能在 `skill-docs` 中定义的所有参数。
- 每个参数应展示：
  - 参数主键（用于 JSON 字段名，例如 `baseManaCost`）；
  - 参数别名列表（例如 `manaCost`），以只读说明形式展示；
  - 类型（INT / DOUBLE / FLOAT 等）；
  - 默认值（来自文档）；
  - 中文说明文本。
- 为每个参数提供输入控件：
  - 数值类型参数使用数字输入框；
  - 布尔或字符串类型后续如出现，再根据实际类型选择控件；
  - 输入框默认填入文档默认值。
- 每个参数提供“使用默认值”勾选框：
  - 勾选时：不将该参数写入 JSON，由服务器端使用默认逻辑；
  - 取消勾选时：使用当前输入框的值写入 JSON。

#### 3.6 JSON 与指令导出（单行）

- 实时生成 JSON 字符串：
  - 仅包含用户选择覆盖的参数；
  - 包括技能参数与通用控制参数；
  - 始终使用单行形式；
  - 键名与大小写严格遵守文档与源码约定。
- 实时生成完整 `/iss cast` 指令：
  - 形如 `/iss cast <caster> <spell_id> <level> [target] {JSON}`；
  - 当目标为空时省略目标参数段；
  - JSON 部分为单行形式。
- 用户操作：
  - 一键复制“完整指令”；
  - 一键复制“仅 JSON”。

#### 3.7 收藏与预设（可选范围）

- 收藏功能：
  - 支持在技能列表中为某个技能加星标；
  - 支持切换“只看收藏”视图。
- 参数预设功能（可作为后续迭代）：
  - 将当前技能的参数配置保存为命名预设；
  - 下次选择该技能时可一键应用预设。

### 4. 非功能需求

- 界面尽量保持简单、直观，重点突出参数与导出指令。
- 不强依赖外部服务，优先使用静态文件或本地后端提供的数据。
- JSON 输出严格符合 Minecraft 命令行可用的格式：
  - 单行；
  - 使用双引号；
  - 无多余注释。

## 二、产品设计与评审文档（PDR）

### 1. 整体架构设计

#### 1.1 架构概览

```
+---------------------------------------------------------------+
|                施法指令生成 Web 页面                          |
+----------------------+----------------------------------------+
                       |
                       v
+----------------------+----------------------------------------+
| 数据加载层                                               |
|  - 从后端或静态资源获取 skill-docs 解析结果               |
|  - 数据结构与 Markdown 文档格式一一对应                   |
+----------------------+----------------------------------------+
                       |
                       v
+----------------------+----------------------------------------+
| 状态与数据模型层                                           |
|  - 当前技能列表                                           |
|  - 当前选中技能定义                                       |
|  - 当前参数配置与控制选项                                 |
|  - 实时生成的 JSON 与指令字符串                           |
+----------------------+----------------------------------------+
                       |
                       v
+----------------------+----------------------------------------+
| 视图与交互层                                              |
|  - 左侧技能列表与搜索                                     |
|  - 右侧技能详情、参数表、说明与导出区                     |
|  - 按钮/输入框/勾选框事件处理                            |
+---------------------------------------------------------------+
```

#### 1.2 前端技术选型

- 使用 TypeScript + 原生 HTML/CSS（初版无需复杂框架）。
- 可以按模块拆分逻辑，但保持实现简单：
  - 一个主入口脚本负责初始化页面与绑定事件；
  - 一个数据模块负责解析/适配后端返回的技能数据；
  - 一个渲染模块负责根据状态刷新视图。

#### 1.3 数据来源设计

- 推荐在构建流程中，将 `skill-docs/*.md` 预解析为结构化 JSON 文件：
  - 例如生成 `docs/skills.json`；
  - 包含所有技能的定义与参数信息。
- Web 页面加载时通过简单的 HTTP 请求获取该 JSON 文件：
  - 避免在浏览器端直接解析 Markdown 的复杂度；
  - 保证前端逻辑聚焦在展示与交互。

### 3. 数据模型设计

#### 3.1 技能定义数据结构

- 技能定义结构（逻辑概念）：
  - 标识：
    - 显示名：例如 `FireballSpell`；
    - 完整 ID：`irons_spellbooks:fireball`；
    - 指令 ID：`fireball`。
  - 文档相关：
    - 原始 Markdown 路径；
    - 技能说明文本列表。
  - 参数列表：
    - 若干参数定义对象。

#### 3.2 参数定义数据结构

- 参数定义结构（逻辑概念）：
  - 主键名（用于 JSON 字段名，例如 `baseManaCost`）；
  - 别名列表（例如 `["manaCost", "baseManaCost"]`）；
  - 类型（INT / DOUBLE / FLOAT 等）；
  - 默认值（数字或字符串）；
  - 中文说明。

#### 3.3 运行时状态结构

- 当前选中技能 ID；
- 当前施法基础配置：
  - caster（字符串）；
  - level（整数）；
  - target（字符串，可空）。
- 当前通用控制参数：
  - consumeMana、triggerCooldown、playEffects、bypassConditions、showCastBar。
- 当前每个参数是否覆盖以及覆盖值：
  - 可表示为键到配置对象的映射。
- 实时派生出的 JSON 字符串与指令字符串：
  - 不单独存储，可由状态计算得到。

### 4. 关键交互流程

#### 4.1 初始化流程

1. 页面加载时请求技能列表与参数数据（例如从 `skills.json`）。
2. 将数据转为内部数据模型，存入状态。
3. 默认选中第一个技能，渲染右侧详情。

#### 4.2 切换技能流程

1. 用户在左侧列表点击某技能；
2. 更新当前选中技能 ID；
3. 重置该技能的参数覆盖状态为“均使用默认值”（或保留上次选择，可配置）；
4. 右侧展示新的技能基本信息、说明与参数表；
5. 重新计算 JSON 与指令预览。

#### 4.3 修改参数流程

1. 用户修改施法基础配置或通用控制参数：
   - 更新对应状态；
   - 基于新状态重新计算 JSON 与指令预览。
2. 用户在参数表中修改某行的值或勾选“使用默认值”：
   - 若勾选“使用默认值”：从覆盖状态中移除该字段；
   - 若取消勾选并填写数值：更新覆盖状态中该字段。
3. 每次参数变化时：
   - 使用覆盖状态 + 通用控制参数构造一个对象；
   - 序列化为单行 JSON 字符串；
   - 拼接 `/iss cast` 指令。

#### 4.4 导出流程

1. 用户点击“复制指令”按钮：
   - 使用浏览器剪贴板 API 将当前指令复制到剪贴板；
   - 可选：显示短暂提示“已复制”。
2. 用户点击“仅复制 JSON”：
   - 将单行 JSON 字符串复制到剪贴板。

### 5. 与现有系统的一致性

- 技能参数来源：
  - 严格依赖 `skill-docs/*.md` 中的参数表；
  - 不自行发明新的参数名。
- 指令格式：
  - `/iss cast` 指令及选项字段与现有文档保持一致；
  - 不修改命令语义，只负责生成。
- 参数覆盖行为：
  - 通过生成符合 SpellParameters 约定的 JSON 字段完成；
  - 不触碰服务端配置与代码逻辑，只作为工具辅助。

### 6. 风险与扩展

- 风险点：
  - `skill-docs` 格式若后续调整，需要同步更新解析规则与数据模型；
  - 若未来新增复杂类型参数（数组、对象），前端控件需要扩展。
- 可扩展方向：
  - 为特定技能提供专用的参数编辑组件（例如坐标选择器、目标选择器）。
  - 支持导入/导出一组预设，方便在不同服务器或存档间迁移配置。
  - 增加“示例区”，直接展示基于当前参数生成的一些推荐指令片段。
